The one idea

The core inversion

The orchestrator owns every transition, validation decision, and retry limit. Agents cannot advance workflow state themselves. Agents are disposable workers that produce validated outputs; the engine decides what happens next.

Source: README.md §Workflow

The canonical pipeline

Every route begins with exploration and planning; only approved mutation routes continue into checks and mutation:

Explore→ Plan→ Plan review→ Human gate→ Check setup→ Baseline→ Tester→ Builder→ Review + fixes→ Docs→ Final checks→ Worktree sync
  • Deferred check setup: read-only and planning-only routes run neither checks nor mutation agents. Check setup happens only after a mutation route's plan is approved.
  • Human gates (plan approval, check setup, diagnosis approval, memory approval) pause the workflow; Mission Control closes and reopens around them.

Agent roles

Read-onlyExplorer, Planner, Reviewer, Debugger, Interviewerread, grep, find, ls
Mutation (exact-path authorized)Tester, Builder, Documenter+ write, edit, only on plan-files
  • Roles run as in-memory Pi SDK sessions, not subprocesses; nested extensions/skills/prompt-templates/shell are disabled.
  • Project checks are orchestrator-owned pi.exec calls, never agent shell access.
  • Plan files / testSupportFiles are exact repository-relative mutation permissions — not directories, not globs.

The two UIs

Mission Control (TUI overlay)
Full-screen on-demand overlay via /orchestrator-control; compact one-line footer status always visible. Read-only; Tab selects an agent, Enter inspects the transcript, Esc closes. Auto-closes/reopens at decision points.
Browser dashboard (React + SSE)
Optional, binds 127.0.0.1, streams live state over Server-Sent Events. Tabs: Overview, Agents, Timeline, Artifacts. Read-only operations console.

Front doors

  • /orchestrate — collect route + request, then return immediately; the workflow runs in the background.
  • /requirements — interactive interview (question hub + dashboard race) that can hand off into a workflow.
  • /orchestrator-resume — continue a paused/failed/cancelled run from its latest validated checkpoint.

Persistence & safety, in one line each

  • Run artifacts: .pi/orchestrator/runs/<run-id>/ — versioned state, events, transcripts, patches, immutable checkpoint-*.json files.
  • Resume fails closed on any safety binding mismatch (worktree, digest, lease, finalization risk).
  • Worktree isolation: mutation runs in a detached worktree; the main workspace updates only after final checks pass.
  • Fail closed: malformed config, state, memory, or checkpoints are reported, never silently replaced.

Glossary

route
A fixed phase template (e.g. implementation); the user picks one; the orchestrator owns its phase sequence.
phase
A step of the canonical pipeline (Explore, Plan, Baseline, …).
role session
One in-memory Pi SDK agent session with a fixed capability class and a task envelope.
task envelope
The versioned JSON contract sent to every role session; its task object is authoritative, memoryContext is advisory.
human gate
A workflow pause awaiting an explicit human decision (plan approval, check setup, diagnosis, memory).
check
An orchestrator-owned pi.exec project command (test, typecheck, lint, build).
baseline
The green check-run the mutation phase must start from.
checkpoint
Immutable numbered validation boundary enabling /orchestrator-resume.
worktree isolation
Running mutations in a Git worktree so the main workspace is untouched until final checks pass.
fail closed
On any invalid/uncertain state: report, refuse, and never guess or overwrite.
